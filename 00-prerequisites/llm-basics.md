# 用一条问答认识 LLM 的基本概念

配合[复旦 NLP 教材](https://intro-llm.github.io/)选读。本页用例子解释入门名词，不替代教材中的完整定义与推导。

## 从模型的一次回答开始

用户输入：“小明有 2 个苹果，又买了 3 个，现在有几个？”

模型生成：“2 + 3 = 5，所以有 5 个苹果。”

| 名词 | 在这个例子里是什么意思 |
| --- | --- |
| token | 模型处理文本的单位，可能是一个字、一个词的一部分或标点，具体划分由 tokenizer 决定 |
| tokenizer | 将文本转换为 token 编号、再把编号转回文本的工具 |
| 参数 | 模型在训练中学到的数值，不是一份可以直接查询的问答表 |
| 推理（inference） | 使用已有参数生成回答；普通推理不更新模型参数 |
| prompt | 提供给模型的输入，可以包含任务说明、上下文和问题 |
| 上下文长度 | 一次请求能够处理的 token 范围；可用输入长度还受输出预算与服务配置影响 |

生成式语言模型逐步预测后续 token。这是训练与生成机制的起点，不表示生成的每句话都正确；还需要核对任务答案与证据。

## 预训练、SFT、LoRA 和 RAG 有什么关系

**预训练**让模型从大量文本中学习语言规律与知识。以常见的自回归语言模型为例，训练目标是预测后续 token。

**SFT（有监督微调）**使用输入与目标回答继续训练模型。上面的问答可以写成一条教学样本：

```json
{
  "instruction": "小明有 2 个苹果，又买了 3 个，现在有几个？",
  "output": "2 + 3 = 5，所以有 5 个苹果。"
}
```

这只是数据格式的一种示例；不同训练工具可能使用 `messages` 等字段。准备数据时，要检查格式和工具要求是否一致，也要检查回答内容是否正确。

**LoRA**是一种参数高效微调方法：冻结原有权重，训练附加的低秩参数。它可以用于 SFT；SFT 描述训练任务，LoRA 描述如何更新参数，两者不是互斥选项。

**RAG（检索增强生成）**先查找资料，再把检索结果放进模型上下文。例如回答课程安排前先检索课程文档。单纯新增或检索文档，不等于微调模型；一些完整系统也可能另外训练检索器或生成器。

## 训练集、验证集和测试集

- **训练集**：用于拟合模型、学习参数。
- **验证集**：用于选择配置、阈值和 checkpoint；它应与训练集分开。
- **测试集**：实验方案确定后用于评估。不要根据测试答案逐条调整数据或参数，再把同一测试分数当作独立检验。

**数据泄漏**会让评估看起来比实际更好。例如训练数据里包含测试题及答案，或者同一篇文档的近重复版本跨越了不同划分。划分数据时，除了随机抽样，还要考虑重复内容、文档来源和时间。

**loss**衡量模型输出与训练目标之间的差异。训练 loss 降低说明模型更贴合当前训练目标，不保证新题回答更好；还要查看验证结果与具体错误。

**checkpoint**是某个训练时刻保存的模型状态。通常依据验证集选择，最终再在测试集上报告结果。

## “数据更好”应该怎样验证

假设你发现训练回答把 2 + 3 标成了 6，修正这条标签是合理的数据工作。但要判断修正是否对整体任务有帮助，还需要：

1. 保持模型方法、评测规则和独立测试集一致。
2. 记录数据改了什么、剩下多少条，尽量每次只改变一个因素。
3. 比较任务分数，并检查修正了哪些错误、又新增了哪些错误。
4. 数据量改变时，考虑加入相同数据量的随机抽样对照；正式结论还要考虑随机种子和更多数据。

去重即使没有提高某次正确率，也可能减少存储或训练开销。相反，过滤后分数提高，也不能直接说明某种过滤规则在所有任务上都有效。
